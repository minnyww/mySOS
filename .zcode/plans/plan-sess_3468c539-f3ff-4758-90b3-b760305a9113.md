# แผนสร้างแอป MySOS (Flutter + Firebase + LINE OA + BoostSMS)

## สรุประบบ
แอป Flutter ชุดเดียวรันทั้ง iOS + Android มี 2 บทบาทในแอปเดียว: **ผู้ใช้** (คนที่อาจต้องขอความช่วยเหลือ เช่น ผู้สูงอายุ) และ **ผู้ดูแล** เชื่อมกันด้วย **QR code + รหัส 6 หลัก** เมื่อผู้ใช้กด SOS (จากในแอป หรือจาก Widget หน้าจอหลัก) ระบบแจ้งเตือนผู้ดูแลพร้อมกัน 3 ช่องทาง: **FCM push, LINE OA, SMS (BoostSMS)**

## เทคโนโลยีที่เลือก
- **Flutter** + flutter_riverpod (state), ธีมภาษาไทย ฟอนต์ Sarabun ตัวใหญ่ คอนทราสต์สูง เหมาะกับผู้สูงอายุ
- แพ็กเกจหลัก: firebase_core / firebase_auth (anonymous) / cloud_firestore / firebase_messaging, mobile_scanner (สแกน QR), qr_flutter (สร้าง QR), home_widget (Widget iOS+Android), flutter_local_notifications, geolocator (แนบพิกัด GPS ในแจ้งเตือน — ขอสิทธิ์ตอนใช้งาน ปฏิเสธได้ แจ้งเตือนยังส่งได้), url_launcher (กดโทร/เปิดแผนที่/เปิด LINE)
- **Cloud Functions** (TypeScript, Node 20): `onAlertCreated` (fan-out 3 ช่องทาง), `onPairAccepted`, `lineWebhook` (HTTPS + ตรวจ signature HMAC), `ackAlert`
- **BoostSMS**: `POST https://app.boost-sms.com/api/v1/sms/send`, header `Authorization: Bearer <API_KEY>`, body `{recipient, message, senderName}` (rate 10 req/min — เพียงพอ) หมายเหตุ: SMS ภาษาไทยจำกัด 70 ตัวอักษร/ข้อความ ข้อความ SOS จะออกแบบให้สั้น + ลิงก์แผนที่

## โมเดลข้อมูล (Firestore)
- `users/{uid}`: role, displayName, phone, fcmTokens[], lineUserId, caregiverUids[] (denormalize เพื่อให้ security rules ตรวจสิทธิ์ได้)
- `pairs/{code6}`: ownerUid, createdAt, expiresAt (10 นาที), acceptedBy — rules บังคับว่าผู้ดูแลเขียนได้เฉพาะ uid ตัวเอง และเฉพาะตอนยังว่าง/ไม่หมดอายุ
- `alerts/{id}`: userId, userName, ts, location, status (active/acked), channels {fcm, line, sms: สถานะส่งแต่ละช่องทาง}
- เขียน Security Rules เคร่งครัด และรัน audit ด้วย skill `firebase-security-rules-auditor` ก่อนจบงาน

## ฟลูหลักของระบบ
1. **จับคู่**: ฝั่งผู้ใช้แสดง QR (ฝัง deep link) + รหัส 6 หลักหมดอายุ 10 นาที → ผู้ดูแลสแกน QR (mobile_scanner) หรือพิมพ์รหัส → function สร้างความสัมพันธ์ + ยืนยันทั้งสองฝั่ง
2. **SOS**: ปุ่มใหญ่ในแอป กดแล้วนับถอยหลัง 3 วิ ยกเลิกได้ (กันกดพลาด) → เขียน alert ลง Firestore (มี offline persistence) → function fan-out: FCM high-priority + LINE push (มีปุ่มโทร/เปิดแผนที่) + SMS — ผู้ดูแลกด "รับทราบ" แล้วฝั่งผู้ใช้เห็นสถานะทันที
3. **เชื่อม LINE**: ผู้ดูแลกดปุ่มเพิ่มเพื่อน OA → พิมพ์รหัสจากแอปส่งในแชท OA → webhook จับคู่ lineUserId → รับ push จาก OA ได้นับแต่นั้น

## Widget หน้าจอหลัก
- **Android**: layout XML + HomeWidgetProvider — แก้ไฟล์ได้เองทั้งหมด ไม่ต้องเปิด Android Studio
- **iOS**: WidgetKit extension (SwiftUI) — เขียนไฟล์ .swift ให้ครบ + พยายามแก้ project.pbxproj อัตโนมัติ หากไม่เสถียรจะเหลือขั้นตอนเปิด Xcode เพิ่ม target (~2 นาที) ตามที่ README ระบุ
- ข้อจำกัดที่แจ้งก่อน: iOS ไม่อนุญาตให้ widget ส่ง network เองตอนแตะ ทั้งสองแพลตฟอร์มใช้แนวทาง "แตะ Widget → เปิดแอปเข้าโหมดส่งอัตโนมัติทันที (~2 วิ)" เป็น MVP
- กันสแปม: alert ใหม่ห่างเดิมอย่างน้อย 60 วินาที

## สิ่งที่คุณต้องเตรียมเอง (โค้ดผมทำรอไว้ให้ครบ + คู่มือทีละขั้นใน README)
- โปรเจกต์ Firebase แผน Blaze (โควตาฟรีในตัว ไม่มีค่าใช้จ่ายจนเกินโควตา) + อัปโหลด APNs key สำหรับ push iOS
- LINE Messaging API channel (ได้ channel secret/token จาก developers.line.biz ฟรี) + ตั้ง webhook URL
- บัญชี BoostSMS + API key (ทดลองฟรี 100 ข้อความ) — ถ้ายังไม่กรอก key ระบบข้ามช่องทาง SMS เองโดยไม่พัง

## ลำดับการทำงาน (7 เฟส)
1. **Scaffold**: `git init` แยกใน mysos/ (repo playground แม่สถานะไม่เรียบร้อย จะไม่แตะ), flutter create (com.mysos.app), ธีมไทย, navigation, โครงหน้าจอทั้งหมด (เลือกบทบาท / หน้าหลักผู้ใช้ / จับคู่ / สแกน / หน้าหลักผู้ดูแล / รายละเอียดแจ้งเตือน / ตั้งค่า)
2. **Firebase**: init + anonymous auth + data layer + security rules + audit
3. **จับคู่** QR/รหัส ครบทั้งสองฝั่ง
4. **ฟลู SOS** + ประวัติ + ปุ่มรับทราบ + แจ้งเตือนฝั่งผู้ดูแล (เสียง/แสดงตอนแอปเปิดอยู่)
5. **Cloud Functions**: FCM fan-out, LINE webhook/push, BoostSMS adapter (อ่านคีย์จาก env, ไม่มีคีย์ก็ข้าม)
6. **Widgets** Android + iOS + deep link auto-SOS
7. **ตรวจรับ**: `flutter analyze`, unit/widget test ของฟลูหลัก, ทดสอบ functions กับ emulator, ทดสอบบน Android emulator, เขียน README ครบทุกขั้นตอนตั้งค่า

## การตรวจรับผลงาน
- `flutter analyze` ผ่าน, ทดสอบ unit/widget ผ่าน (pairing, countdown, fan-out)

- ตรวจ security rules ด้วย skill auditor ก่อนส่งมอบ
